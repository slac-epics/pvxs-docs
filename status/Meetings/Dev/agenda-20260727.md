# SPVA Dev Meeting - Agenda

**Scheduled:** Monday, July 27, 2026 at 09:00 PDT

**Primary focus:** Agree the release plan for secure PVXS and resolve the remaining practical implementation questions.

## 1. Secure PVXS Release Scope and Sequencing

Discussion: Response to Kay's questions about releasing secure PVXS with only `authnstd`, before considering additional authentication methods such as JSON Web Token support.

Questions:

- What does release of `authnstd` actually involve?
- What functionality is required for the first secure PVXS release?
- When we are talking about PVXS, we are talking about PVXS-CMS as well, although there is no work underway to integrate that into the EPICS base GitHub organisation. What, if anything, do we need to do to address this gap?
- Is `authnstd` sufficiently complete for administrators to create and use compatible certificates?
- Are changes required in EPICS base before release?
- Are any current design decisions likely to make an `authnstd` release incompatible with future authentication methods?
- Should support for additional authentication methods be treated as separate future work rather than part of the initial release?
- Note the agreement on removal of the `-D` option from `authnstd` and the renewal semantics.

Outcome sought:

- Agree the intended scope of the first secure PVXS release.
- Identify remaining blocking work, which dovetails into the pull request 171 discussion later.
- Agree whether a release date or release-readiness review can be scheduled.
- Record future authentication methods as separate follow-up work unless they are release blockers.

## 2. SPVA Version: Practical Implementation

Discussion: Continue the version-number discussion and resolve how the shared SPVA version is represented across projects.

Questions:

- Where is the normative SPVA version defined?
- Where is it recorded in PVXS, Phoebus, PVXS-CMS, and possibly P4P?
- How is the version expressed in source code, runtime protocol identifiers, configuration paths, and documentation?
- How do the projects verify that they are using compatible versions? Consider rules and automatic migration.
- What event causes the SPVA version to be incremented?
- How are older versions supported during a transition?

Outcome sought:

- Agree the normative source for the SPVA version.
- Agree the representation used by each project.
- Agree the compatibility and version-increment rules.
- Vote on the previously drafted resolutions, if the wording is ready.
