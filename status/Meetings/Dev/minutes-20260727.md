## TOPIC: CERTIFICATE ISSUANCE WORKFLOW (SELF-SERVICE VS ADMINISTRATOR-MINTED)

### Minutes

- Michael: the current self-service two-step issuance (user mints, admin approves) lacks a way
  for an administrator to **query certificate details before approving**, making it
  untrustworthy for rollout at ALS.
- Michael proposed a minimal addition - a pvxget or RPC command letting an admin verify a
  certificate (creation time, username, allowed usages) by hash before approving. Ernesto
  agreed it would be a useful sanity check; George noted it can be **added later without
  breaking the interface**; Gregory suggested staying focused on the FY26 minimum set.
- Michael proposed the sanctioned FY26 workflow: **the administrator mints the certificate and
  hands off the PKCS#12 (P12) file** to the user. Ernesto agreed - a single designated person
  (e.g. himself or Jingchen) can handle issuance until the Kerberos-based approach arrives next
  year.

### Resolutions

- Sanctioned FY26 workflow: **administrator mints the certificate and hands off the P12 file**.
- The self-service workflow remains available but is **not officially sanctioned** (identity
  verification limitations).
- The admin certificate-query feature (hash verification) is desirable but **deferred**; it can
  be added later without interface changes.

## TOPIC: SPVA VERSION SPECIFICATION (agenda item 2)

### Minutes

- Michael argued for **two separate version specifications** - wire protocol and file
  system/configuration usage - as they are loosely coupled. George agreed and suggested
  surfacing them in tool output (e.g. a `-V` flag).
- Michael clarified `-V` output should show **module/source versions**, not protocol versions;
  runtime protocol version visibility belongs in tools like **pvxinfo** (and could be added).
- Version negotiation: **ALPN negotiation** handles this for TLS; the PVA protocol uses a
  "minimum of the two highest supported versions" approach.
- George proposed major-version = incompatible, minor-version = compatible; Michael was
  uncertain major/minor semantics apply cleanly (citing the Channel Access protocol minor
  version as an example of nuanced versioning). Gregory noted versioning is too complex to
  fully resolve in this meeting.

### Resolutions

- **Two version specifications** will be defined: wire protocol, and file system/config.
- They will be documented in the **SPVA interface Google Doc** (Michael's notes), potentially
  as two subsections of one document.
- Wire-protocol version negotiation uses **ALPN**; runtime protocol version can be surfaced via
  pvxinfo.

### Issues

- Detailed version rules (major/minor semantics) are **deferred** - no resolution reached.
